## System Prompt Structure

The system prompt is the foundational instruction set sent to the AI model before any user interaction. It defines the AI's role, capabilities, rules, and available tools.

### System Prompt Generation

**Location**: `src/core/prompts/system.ts`

The system prompt is generated by the `SYSTEM_PROMPT` function, which combines multiple sections:

```typescript
async function generatePrompt(
    context: vscode.ExtensionContext,
    cwd: string,
    supportsComputerUse: boolean,
    mode: Mode,
    mcpHub?: McpHub,
    diffStrategy?: DiffStrategy,
    // ... other parameters
): Promise<string>
```

### System Prompt Components

The system prompt is assembled from the following sections in this order:

#### 1. Role Definition
- **Source**: `getModeSelection()` from mode configuration
- **Purpose**: Defines the AI's primary role (e.g., code editor, architect, debugger)
- **Example**: "You are Kilo, a highly skilled software engineer with extensive knowledge in many programming languages, frameworks, design patterns, and best practices."

#### 2. Markdown Formatting Section
- **Source**: `markdownFormattingSection()`
- **Purpose**: Instructs AI on how to format responses
- **Content**: Guidelines for using code blocks, headings, lists, etc.

#### 3. Shared Tool Use Section
- **Source**: `getSharedToolUseSection(toolUseStyle)`
- **Purpose**: Explains how to use tools (XML or JSON format)
- **Content**: 
  ```
  TOOL USE
  
  You have access to a set of tools that are executed upon the user's approval. 
  You must use exactly one tool per message, and every assistant message must 
  include a tool call.
  ```

#### 4. Tool Descriptions
- **Source**: `getToolDescriptionsForMode()`
- **Purpose**: Lists all available tools with their parameters and usage
- **Location**: `src/core/prompts/tools/`
- **Tools include**:
  - `read_file` - Read file contents
  - `write_to_file` - Create or overwrite files
  - `edit_file` - Make surgical edits to files
  - `search_files` - Regex search across files
  - `list_files` - List directory contents
  - `execute_command` - Run terminal commands
  - `ask_followup_question` - Ask user for clarification
  - `attempt_completion` - Complete the task
  - `browser_action` - Interact with web browsers
  - `codebase_search` - Semantic code search
  - And more...

**Example Tool Description** (read_file):
```
## read_file
Description: Request to read the contents of a file at the specified path. Use this when you need to examine the contents of an existing file, for example to analyze code, review text files, or extract information from configuration files. Automatically extracts raw text from PDF and DOCX files. May not be suitable for other types of binary files, as it returns the raw content as a string.
Parameters:
- path: (required) The path of the file to read (relative to the current working directory {cwd})
Usage:
<read_file>
<path>File path here</path>
</read_file>
```

#### 5. Tool Use Guidelines
- **Source**: `getToolUseGuidelinesSection()`
- **Purpose**: Best practices for using tools effectively
- **Content**: Instructions on when and how to use specific tools

#### 6. MCP Servers Section (if available)
- **Source**: `getMcpServersSection()`
- **Purpose**: Documents available MCP (Model Context Protocol) servers and their capabilities
- **Content**: Lists external tool servers and resources available

#### 7. Capabilities Section
- **Source**: `getCapabilitiesSection()`
- **Purpose**: Describes AI's overall capabilities
- **Example Content**:
  ```
  CAPABILITIES
  
  - You have access to tools that let you execute CLI commands on the user's 
    computer, list files, view source code definitions, regex search, read 
    and write files, and ask follow-up questions.
  - When the user initially gives you a task, a recursive list of all 
    filepaths in the current workspace directory will be included in 
    environment_details.
  - You can use search_files to perform regex searches across files...
  ```

#### 8. Modes Section
- **Source**: `getModesSection()`
- **Purpose**: Explains available modes and how to switch between them
- **Content**: Lists all modes (code, architect, ask, debug, etc.) with descriptions

#### 9. Rules Section
- **Source**: `getRulesSection()`
- **Purpose**: Critical rules and constraints the AI must follow
- **Example Rules**:
  ```
  RULES
  
  - The project base directory is: /path/to/workspace
  - All file paths must be relative to this directory
  - Before using execute_command, think about SYSTEM INFORMATION context
  - When using search_files tool, craft regex patterns carefully
  - When creating a new project, organize files within a dedicated directory
  - For editing files, prefer surgical edits over complete rewrites
  - Do not ask for more information than necessary
  - NEVER end attempt_completion with a question
  - You are STRICTLY FORBIDDEN from starting messages with "Great", "Certainly"
  ```

#### 10. System Information Section
- **Source**: `getSystemInfoSection()`
- **Purpose**: Provides environment details
- **Content**: Operating system, shell, architecture, home directory

#### 11. Objective Section
- **Source**: `getObjectiveSection()`
- **Purpose**: Defines how to approach tasks
- **Content**:
  ```
  OBJECTIVE
  
  You accomplish a given task iteratively, breaking it down into clear steps.
  
  1. Analyze the user's task and set clear, achievable goals
  2. Work through these goals sequentially, utilizing available tools
  3. Remember, you have extensive capabilities with access to tools
  4. Once completed, use attempt_completion tool to present results
  5. The user may provide feedback for improvements
  ```

#### 12. Custom Instructions
- **Source**: `addCustomInstructions()`
- **Purpose**: User-defined instructions and rules
- **Content**: 
  - Mode-specific base instructions
  - Global custom instructions from settings
  - Local `.kilocode/rules/*.md` files
  - Global rules from user config
  - `.rooignore` instructions

## Context Handling Mechanisms

Kilocode uses several mechanisms to provide context to the AI model. Each mechanism handles context differently based on the source.

### 1. File Mentions (`@/path/to/file.ts`)

**Processing Flow**:
1. User types `@/path/to/file.ts` in chat input
2. `parseMentions()` function is called (`src/core/mentions/index.ts`)
3. Function reads file contents using `extractTextFromFile()`
4. Content is wrapped in XML tags and appended to user message

**Implementation** (`src/core/mentions/index.ts`):
```typescript
export async function parseMentions(
    text: string,
    cwd: string,
    urlContentFetcher: UrlContentFetcher,
    fileContextTracker?: FileContextTracker,
    // ... other parameters
): Promise<string>
```

**Output Format**:
```xml
Original mention in text: '@/src/utils.ts' (see below for file content)

Appended to message:
<file_content path="src/utils.ts">
1. import { someFunction } from './helpers'
2. 
3. export function myFunction() {
4.   // function implementation
5. }
</file_content>
```

**File Context Tracking**:
- Files mentioned via `@` are tracked in `FileContextTracker`
- This tracks when files are modified outside of Kilocode
- Prevents stale context issues with diff editing
- Location: `src/core/context-tracking/FileContextTracker.ts`

### 2. Folder Mentions (`@/path/to/folder/`)

**Processing Flow**:
1. User types `@/path/to/folder/` (note trailing slash)
2. `parseMentions()` detects it's a directory
3. Reads directory structure recursively
4. Includes file tree AND contents of non-binary files

**Output Format**:
```xml
Original mention: '@/src/components/' (see below for folder content)

Appended to message:
<folder_content path="src/components">
├── Header.tsx
├── Footer.tsx
└── Button.tsx

<file_content path="src/components/Header.tsx">
import React from 'react'
export const Header = () => {
  return <header>My App</header>
}
</file_content>

<file_content path="src/components/Footer.tsx">
import React from 'react'
export const Footer = () => {
  return <footer>© 2024</footer>
}
</file_content>

<file_content path="src/components/Button.tsx">
import React from 'react'
export const Button = ({ text }) => {
  return <button>{text}</button>
}
</file_content>
</folder_content>
```

**Notes**:
- Binary files are skipped
- Locked files (in `.kilocodeignore`) are shown with 🔒 icon
- Only files in the directory are included, subdirectories show structure only

### 3. Problems Mention (`@problems`)

**Processing Flow**:
1. User types `@problems`
2. `parseMentions()` calls `getWorkspaceProblems()`
3. Retrieves diagnostics from VS Code's Problems panel
4. Formats errors and warnings with file paths and line numbers

**Output Format**:
```xml
Original mention: 'Workspace Problems' (see below for diagnostics)

Appended to message:
<workspace_diagnostics>
src/app.ts:
  Line 10: Error - Cannot find name 'undefinedVar'
  Line 15: Warning - 'unusedVar' is declared but never used

src/utils.ts:
  Line 5: Error - Expected 2 arguments, but got 1
</workspace_diagnostics>
```

**Configuration**:
- `includeDiagnosticMessages`: Include full diagnostic messages (default: true)
- `maxDiagnosticMessages`: Maximum diagnostics to include (default: 50)

### 4. Terminal Mention (`@terminal`)

**Processing Flow**:
1. User types `@terminal`
2. `parseMentions()` calls `getLatestTerminalOutput()`
3. Selects all terminal content, copies to clipboard
4. Cleans up command separation and formatting

**Output Format**:
```xml
Original mention: 'Terminal Output' (see below for output)

Appended to message:
<terminal_output>
$ npm run build
> my-app@1.0.0 build
> tsc && vite build

vite v4.3.0 building for production...
✓ 34 modules transformed.
dist/index.html                   0.45 kB
dist/assets/index-a1b2c3d4.js   142.33 kB │ gzip: 45.67 kB
✓ built in 1.23s
</terminal_output>
```

**Note**: Original clipboard content is restored after capture

### 5. Git Mentions

#### Git Commit (`@a1b2c3d`)

**Processing Flow**:
1. User types `@` followed by 7-40 character hex string
2. Recognized as git commit hash
3. `getCommitInfo()` executes `git show <hash>`
4. Returns commit metadata and diff

**Output Format**:
```xml
Original mention: 'Git commit 'a1b2c3d'' (see below for commit info)

Appended to message:
<git_commit hash="a1b2c3d">

Author: John Doe <john@example.com>
Date:   Mon Jan 1 12:00:00 2024 +0000

    Add user authentication

--- /dev/null
+++ b/src/auth.ts
@@ -0,0 +1,10 @@
+export function authenticate(user: string) {
+  // implementation
+}
</git_commit>
```

#### Working Changes (`@git-changes`)

**Processing Flow**:
1. User types `@git-changes`
2. `getWorkingState()` executes `git status` and `git diff`
3. Shows both staged and unstaged changes

**Output Format**:
```xml

Appended to message:

+export function newFunction() {

```

### 6. URL Mentions (`@https://example.com`)

**Processing Flow**:
1. User types `@https://example.com`
2. `parseMentions()` launches headless browser
3. `urlContentFetcher.urlToMarkdown()` fetches and converts page
4. Removes scripts, styles, navigation elements
5. Converts HTML to clean Markdown

**Output Format**:
```xml
Original mention: '@https://example.com' (see below for site content)

Appended to message:
<url_content url="https://example.com">
# Example Website

Welcome to our site...

## Features
- Feature 1
- Feature 2

[Learn More](#)
</url_content>
```

**Error Handling**:
- Timeout errors
- DNS resolution failures
- 403/404 HTTP errors
- All errors shown to user with localized messages

### 7. Command Mentions (`@commandName`)

**Processing Flow**:
1. User types `@commandName`
2. System checks if command exists in `.kilocode/commands/`
3. If exists, loads command content and description
4. Command content appended to message

**Output Format**:
```xml
Original mention: "Command 'deployScript' (see below for command content)"

Appended to message:
<command name="deployScript">
Description: Deploy the application to production

#!/bin/bash
npm run build
rsync -avz dist/ user@server:/var/www/app/
</command>
```

**Location**: Commands stored in `.kilocode/commands/` directory

### 8. Image Mentions (`@image`)

**Processing Flow**:
1. User selects an image file
2. Image is converted to base64 encoding
3. Added to message as image block (not text)
4. AI uses vision capabilities to analyze

**Format**: Images are added as `ImageBlockParam` in the conversation, not as text content

## User Input Processing

### Message Flow

When a user sends a message, it goes through multiple processing stages before reaching the AI:

**Location**: `src/core/task/Task.ts` (method: `startTask()` and message handling)

#### Stage 1: Initial Message Reception
```typescript
// User input arrives as text + optional images
task: string
images?: string[]
```

#### Stage 2: Mention Parsing
```typescript
// Process @ mentions in user content
const [parsedUserContent, needsRulesFileCheck] = 
    await processKiloUserContentMentions({
        context: this.getContext(),
        userContent: currentUserContent,
        cwd: this.cwd,
        urlContentFetcher: this.urlContentFetcher,
        fileContextTracker: this.fileContextTracker,
        // ... other parameters
    })
```

**Function**: `processKiloUserContentMentions()` in `src/core/mentions/processKiloUserContentMentions.ts`

**What it does**:
1. Detects `@` mentions in text within `<task>` or `<feedback>` tags
2. Calls `parseMentions()` for each mention type
3. Processes Kilo-specific slash commands (e.g., `/newrule`)
4. Returns expanded content with all mentions resolved

#### Stage 3: Environment Details Addition
```typescript
const environmentDetails = await getEnvironmentDetails(
    this, 
    currentIncludeFileDetails
)
```

**Environment Details Include**:
- Recursive file tree of workspace
- Current working directory
- Shell and OS information
- Available commands

**Example**:
```xml
<environment_details>
# VSCode Visible Files
src/app.ts
src/utils.ts

# VSCode Open Tabs
src/app.ts
src/utils.ts
README.md

# Current Working Directory ({cwd}) Files
src/
  app.ts
  utils.ts
  components/
    Header.tsx
    Footer.tsx
package.json
README.md
</environment_details>
```

#### Stage 4: Final User Content Assembly
```typescript
const finalUserContent = [
    ...parsedUserContent,  // User text + resolved mentions
    { 
        type: "text" as const, 
        text: environmentDetails 
    }
]
```

#### Stage 5: API Conversation History Update
```typescript
await this.addToApiConversationHistory({ 
    role: "user", 
    content: finalUserContent 
})
```

**Conversation Structure**:
```typescript
apiConversationHistory: ApiMessage[] = [
    {
        role: "user",
        content: [
            { type: "text", text: "User's message with mentions resolved" },
            { type: "text", text: "<environment_details>...</environment_details>" },
            { type: "image", source: { ... } }  // if images included
        ]
    },
    {
        role: "assistant",
        content: [
            { type: "text", text: "AI's thinking process" },
            { type: "tool_use", id: "...", name: "read_file", input: { ... } }
        ]
    },
    {
        role: "user",
        content: [
            { 
                type: "tool_result", 
                tool_use_id: "...", 
                content: "File contents or tool output" 
            }
        ]
    }
    // ... conversation continues
]
```

### Scenario 9: Tool Results with Context

When the AI uses a tool, the result is added to the conversation as a tool_result:

**AI Tool Use**:
```xml
<read_file>
<path>src/config.ts</path>
</read_file>
```

**System Response** (added to conversation):
```json
{
  "role": "user",
  "content": [
    {
      "type": "tool_result",
      "tool_use_id": "toolu_123abc",
      "content": "export const API_URL = 'https://api.example.com'\nexport const TIMEOUT = 5000"
    }
  ]
}
```

**If User Provides Feedback** (after tool rejection):
```xml
<tool_result>
<tool_use_id>toolu_123abc</tool_use_id>
<content>
<feedback>
Actually, please read @/src/config.prod.ts instead
</feedback>
</content>
</tool_result>
```

The `@/src/config.prod.ts` mention is parsed and resolved before being sent back to the AI.

## Summary

### Key Points

1. **System Prompt** is assembled from multiple sections defining role, tools, capabilities, rules, and objectives

2. **Context Mechanisms** include:
   - File mentions (`@/path/to/file`)
   - Folder mentions (`@/path/to/folder/`)
   - Problems mention (`@problems`)
   - Terminal mention (`@terminal`)
   - Git mentions (`@commit-hash`, `@git-changes`)
   - URL mentions (`@https://...`)
   - Command mentions (`@commandName`)
   - Image mentions (vision)

3. **Processing Flow**:
   - User input → Mention parsing → Environment details → API conversation history
   - All mentions resolved to actual content before sending to AI
   - Content wrapped in XML tags for clear structure

4. **File Context Tracking** prevents stale context issues by monitoring external file changes

5. **Conversation Structure** follows Anthropic's message format with alternating user/assistant roles and tool use/results
